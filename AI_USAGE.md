# Використання ШІ

## Інструменти
- Google Gemini.

## Журнал використання

1. **Етап:** Базова інфраструктура.
   - **Мета:** Створити кросплатформний `docker-compose.yml` (сумісний з macOS та Windows).
   - **Промпт:** «З чого буде краще почати розробку, починай з самого початку файлу покроково, 3 варіант, з docker-compose як потрібно оформити для двух ос».
   - **Що використано:** Структура файлів, налаштування портів та volumes, створення `.gitattributes` для вирішення проблеми з CRLF/LF.
   - **Що змінено/перевірено:** Додано власні шляхи до конфігів, перевірено запуск через `docker compose up -d`.

2. **Етап:** Симулятори на Python.
   - **Мета:** Написати клієнти з підтримкою Last Will, retain та JSON.
   - **Промпт:** «Напиши клієнти з підтримкою JSON та інші потрібні.
   - **Що використано:** Логіка словника `DEVICES`, обробка сценаріїв, підписки актуаторів на `/set`.
   - **Що змінено/перевірено:** Виправлено логічну помилку з відображенням статусу в UI. Перевірено через запуск із аргументом `--scenario`.

3. **Етап:** Безпека.
   - **Мета:** Налаштувати сертифікати та обмеження доступу.
   - **Промпт:** «Які саме паролі потрібно вписувати після поля "password" : "пароль", також надай код для згенерування пароля».
   - **Що використано:** Скрипт генерації `.sh`, структура файлу ACL, імпорт `ssl` у Python.
   - **Що змінено/перевірено:** Виправлено кілька помилок ШІ. Додано ігнорування перевірки hostname у клієнті Python.

## Помилки ШІ, які я знайшов
1. **Помилка в ACL:** ШІ спочатку записав актуатор `yard_light` як сенсор, надавши йому права на запис телеметрії замість читання команд. Також ШІ надав усім сенсорам право керувати режимом охорони, що суперечило особливій вимозі варіанта. Я помітив це під час перегляду ACL і виправив шляхи вручну.
2. **Слабкий сертифікат:** Скрипт генерації сертифікатів від ШІ викликав помилку `[SSL: CERTIFICATE_VERIFY_FAILED] CA signature digest algorithm too weak` у Python. Я з'ясував, що стандартний алгоритм був застарілим, і виправив скрипт, додавши прапорець `-sha256`.

## Що зроблено без ШІ
Повністю самостійно проводилось розгортання середовища в macOS, робота з терміналом, інтеграція файлів у правильну структуру каталогу. Встановлення аддонів (`MQTT Binding`, `JSONPath Transformation`) та візуальне тестування інтерфейсу в openHAB виконувались вручну без генерації коду.

## Висновок
Використання ШІ значно прискорило написання шаблонного коду, особливо симуляторів на Python та генерацію сертифікатів. Водночас ШІ часто припускається логічних помилок у контексті безпеки. Робота з інструментом навчила мене ретельно перевіряти згенеровані конфігурації. Завдяки розумінню архітектури, я зміг би відтворити цю систему самостійно, користуючись офіційною документацією MQTT та openHAB.
